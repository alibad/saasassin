# Mission 01 outreach kit

These messages recruit evidence and ask for direction. They must not imply that Fider
maintainers, Canny, or any participant has endorsed SaaSassin.

## Fider maintainer discussion

**Title:** Maintainer direction requested: an upstream-first Canny migration mission

**Body:**

> I run SaaSassin, a new coordination project for verified migrations from closed SaaS
> products to credible open-source projects. We selected Canny → Fider as the first
> proving mission because Canny documents export paths and Fider is already the credible
> open project in this category.
>
> This is not a request to begin implementation, and we will not present a fork as a
> replacement. Fider's contribution guide says new feature ideas should begin as a
> suggestion before a GitHub issue, so I am asking for direction first.
>
> Our proposed discovery scope is: interview five current/recent Canny users, recruit one
> design partner with a permissioned export, document a field-level mapping, and build a
> dry-run loss report. Only work accepted through Fider's process would be proposed
> upstream; Canny-specific conversion can remain separate if that is healthier for Fider.
>
> The public charter is: https://saasassin.net/missions/canny-fider
>
> Which channel should we use for the migration proposal, and what constraints or
> ownership expectations should we record before recruiting builders?

## Design-partner invitation

**Subject:** Help test a reversible Canny → Fider migration

SaaSassin is organizing an independent, upstream-first effort to make Fider a credible
migration path from Canny. We are looking for one current or recent Canny operator who
can define must-keep data, review a dry-run loss report, and—only if it passes—test a
reversible migration.

The discovery call takes 30 minutes. We do not need an export on the call, do not commit
real data to GitHub, and will agree access and deletion terms before receiving any sample.
Fider maintainers have not approved implementation scope yet; their direction is the
first gate.

Mission and application: https://saasassin.net/missions/canny-fider

## Builder invitation

Mission 01 is recruiting ten qualified builders for a Canny → Fider migration path.
Useful skills include Go, TypeScript, data migration, validation, privacy, self-hosting,
and documentation. Qualification means naming a bounded problem you can own; there is
no open implementation sprint before maintainer alignment and a real export.

Read the gates and apply: https://saasassin.net/missions/canny-fider

## Qualification and follow-up

- A design partner must operate a real current/recent Canny workspace, identify an export
  path, own permission to use a minimized sample, and name a plausible test window.
- A builder must name a bounded deliverable and show relevant experience or evidence.
- A maintainer response is logged as direction, not endorsement.
- Every applicant receives one of: interview, scoped follow-up, waitlist, or declined.
- No public counter increases until a human verifies the qualification criteria.
