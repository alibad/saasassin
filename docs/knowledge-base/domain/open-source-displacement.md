# Open-source SaaS displacement

## Operating principles

1. Start from the painful job and migration path, not the incumbent interface.
2. Prefer contributing to a credible project over creating another repository.
3. Keep exports lossless and documented so adopters retain an exit path from the replacement too.
4. Separate open product value from sustainable paid hosting, migration, support, and enterprise controls.
5. Verify security, accessibility, deployment, and recovery—not just feature demos.
6. Measure successful migrations and retained usage as the definition of displacement.

## Clean-room boundary

Mission requirements may describe publicly observable outcomes and user needs. Contributors must not copy proprietary source code, private documentation, brand assets, text, or distinctive trade dress. Product names are used only to identify compatibility and migration targets; trademark review is required before public campaigns.

## Mission types

- **Build:** genuine open-source whitespace justifies a new product.
- **Assemble:** strong primitives exist, but the integrated workflow and migration layer do not.
- **Back:** a credible open-source challenger exists and should receive engineering, product, security, or distribution support.
