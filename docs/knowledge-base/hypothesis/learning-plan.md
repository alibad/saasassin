# Learning plan

## Experiment 1: catalog signal

Publish the ranked target catalog and measure which missions generate qualified builder and adopter interest. A target advances only when it attracts both a credible builder and a design partner.

## Experiment 2: back before build

Run the first mission by extending Fider against Canny. Test whether funding migration, deployment, integrations, and polish creates more displacement value than starting a new repository.

## Experiment 3: AI-native greenfield

Launch the Motion replacement as a bounded 60-day challenge. Test whether an AI-native team can deliver a reliable scheduling loop with commodity models and deterministic planning.

## Experiment 4: sensitive-data flagship

Recruit two design partners for an open Dovetail alternative. Test whether self-hosting, durable export, access controls, and research-repository fundamentals create enough pull before attempting broad AI parity.

## Pivot triggers

- Fewer than 10 qualified builder submissions after 500 relevant visits: narrow the audience or change the challenge format.
- Builder interest without design partners: add migration discovery and customer interviews before accepting missions.
- Repositories ship but migrations do not: shift incentives from code milestones to verified adopter outcomes.
- Maintainers resist the model: revise governance, funding terms, or license expectations before adding targets.
