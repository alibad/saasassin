# November 6, 2026

## What We Built

- **Mail:** filter rules that run on every import, with a preview against existing
  mail and an explicit, audited "apply to existing mail"; a contacts book built from
  your mail; multi-select bulk triage with exact undo; mute thread; a click-only
  unsubscribe helper; send-later queue (honestly unsent until a provider is
  connected); and an indexed search that returns the same results without reading
  every message body.
- **Planner:** repeating tasks (daily, weekdays, chosen weekdays, monthly), `.ics`
  calendar import as busy time that updates instead of duplicating on re-import,
  deep/shallow focus hours as a soft scheduling preference, an Insights tab (planned
  vs completed hours, deadline hit rate, most-pushed tasks, estimate accuracy), and
  signed webhooks for applied plans and at-risk tasks.
- **Studies:** automatic low-quality session flags with researcher exclude/keep,
  tree testing with success, directness and first-click results, findings that must
  cite real responses, Maze results import into a closed read-only study, and signed
  webhooks for completed responses and closed studies.
- **Revenue:** contacts on accounts with per-deal roles and speaker linking, a
  single-threaded deal risk, a forecast tab (commit, best case, weighted pipeline by
  month and rep, with audited manager overrides), a unified deal timeline with
  stalled-in-stage detection, signed webhooks, and a retention-due queue.
- **Community:** member-chosen @handles (emails are never shown to other members),
  cursor pagination everywhere with no more silent caps, mute/block and a per-member
  posting rate limit, plan edit and archive with an explicit keep/revoke choice,
  Circle CSV import into pending invites, and cohorts that open spaces and drip
  course lessons.
- All ten products now prove their whole workflow against a real Firestore emulator;
  today added Mail, Planner, Studies, Revenue and Community (18, 19, 17, 27 and 18
  passing scenarios).

## What We Fixed

- Mail: a thread whose reply arrived before the original no longer keeps the "Re:"
  subject; reply drafts now require an existing thread.
- Planner: a task can no longer depend on task ids that don't exist in its
  workspace (including another tenant's ids).
- Revenue: two coaches redacting the same call at once could restore the text the
  first one removed; redaction, stage moves, coaching acknowledgement and tracker
  seeding now run in transactions.
- Community: moderators no longer see member emails in the audit log; names, RSVPs,
  rosters, reports and the directory no longer fall back to email names; mentions no
  longer match inside dotted names or emails; marking notifications read is audited.
- The fleet registry, architecture doc, roadmap and README now describe ten working
  products and the deploy-on-push pipeline instead of gated foundations.

## Key Decisions

- Outbound webhooks across the fleet use one contract: HMAC-SHA256
  `X-SaaSassin-Signature`, HTTPS only, private hosts refused, secret shown once and
  redacted from exports, honest delivery logs, no automatic retries yet.
- Route logic moved into each product's data layer so emulator specs exercise the
  exact code production runs.
- Planner's scheduler version is now `planner-scheduler/1.1.0`; new plans get new
  fingerprints by design.

## Breaking Changes

- Mail imported before today has no List-Id and no search index; filters on List-Id
  skip it, and search falls back to a full scan until a writer runs "Build search
  index".
